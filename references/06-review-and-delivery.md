# 06 审阅与交付

## 在线审阅（关键习惯）

用支持**时间线评论**的在线审阅服务（例：Frame.io）：

- 你在播放时看到不舒服的地方就停下来，直接把评论钉在那个时间点上。
- 好处：不用截图、不用描述「大概在 1 分 20 秒左右」，评论自带时间码和版本。
- 这类服务通常有 API / MCP，Agent 可以自己上传视频、取链接、读评论——**把审阅也变成工作流的一环**，而不是你另开一个软件手工传文件。

### 流程

1. 按本次约定的审阅节点交版本；已授权上传时可继续，不为每个内部草稿自动上传。未授权外传时先提供本地结果。
2. 按约定的受众、访问方式与有效期创建链接并验证。用户要求免登录时再使用相应可见范围；不默认将私密素材公开。
3. 你按时间点评论 → Agent 读取评论 → 对照当前版本修改。
4. 时长发变化时做**版本时间映射**：旧时间码不能直接套到新片。
5. 改完不是只改那一点：检查该段、相邻接点，以及受影响的声音、字幕和覆盖层。

### 常见错误

- 等「定稿」才上传 → 你只能在最后一次性给一堆意见，改起来最贵。
- 审阅渠道与实际需要不符：需要逐帧评论时优先相应平台；用户明确要聊天软件或本地交付时按其要求，不强制换工具。
- 把上一版的链接当新版的链接 → 你审的是旧片。

## 交付物

按当前任务交付所需成果。常见项目包括以下内容，输出与工程放在各自约定目录，不为套表额外扩大任务：

| 内容 | 说明 |
| --- | --- |
| 成片 | 正式导出的文件（不是工程参数） |
| 封面 | 按平台尺寸导出，文案由人拍板 |
| 发布文案 | 标题、正文、话题；只写真实发生的事和真实数字 |
| 逐字稿 | 最终口播文本，便于检索和二次使用 |
| 工程 | 可续改的工程文件 + 依赖说明（字体、素材、插件） |

- 命名带集号和版本，例如 `20260920-第25集-成片V3.mp4`；不要在文件名里写「最终版」「真的最终版」。
- 归档前核验：时长、分辨率、编码、音量对得上；文件能正常播放；sha256 记录在案。
- 工程和输出从制作开始就写进约定目录，已在正确位置的不重复备份或复制。需要跨设备归档时按授权操作并核对完整性；本地保存成功不代表网盘/NAS已同步，未验证就说明同步状态未知。

## 交付之后

需要沉淀经验时，整理反复出现的修改意见；在用户授权后更新其本地 Skill。

- 区分个人偏好、项目选择与通用规则，例如“音效跟随重要动作，避免覆盖口播”；不要把一次例外变成所有项目的硬限制。
- 写回去之后，下一集它就会默认按你的标准做，而不是等你再说一遍。
- 这一步是整套流程里复利最高的动作：你的判断在慢慢变成它的默认值。
