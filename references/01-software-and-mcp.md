# 01 软件与 MCP 准备

目标：让 AI 能「看见」素材、能「动手」剪片子。缺任何一环，后面都是空谈。

## 需要的三件套

1. **一个能干活的 Agent 客户端**：能读写本地文件、能跑命令、能装 MCP。
   - 例：Codex 桌面版（或同类可以访问本地文件系统的 Agent 客户端）。
   - 关键点：它必须能访问你的素材目录和剪辑软件，而不是只能聊天。
2. **能完成本次任务的模型**：根据视觉理解、工具调用、预算与实际样例选择。
   - 用一小段自己的素材测试，再比较可读性、错误率、完成时间和成本。
   - 不按价格推断能力，也不承诺某档模型固定多少小时完成；素材、设备和修改量都会影响结果。
3. **一个原生 AI 友好的剪辑软件**：
   - 判断标准：官方提供 MCP / CLI、Agent 能直接操作时间线，而不是靠模拟鼠标点击。
   - 例：ChatCut 桌面版，可查[桌面端官方文档](https://chatcut.io/docs/desktop-app)。以当前官方文档和实际可调用工具确认能力、版本及计费，不假设充值后必然能完成整套流程。
   - 备用组合：**MG 动画**可用 Remotion 或 Hyperframes；素材处理和合成可用 FFmpeg。各工具的许可证、商业使用条件与算力成本分别核对，不统一称为免费。

## MCP 配置通用步骤

1. 到当前版本的官方文档查 MCP / CLI 指引，确认客户端和操作系统适配。不要照搬其他电脑的地址、端口或配置文件。
2. 在用户授权的范围内按官方方式配置；保留原有条目，凭证使用客户端安全存储或官方推荐机制，不放进项目文档。
3. 按官方步骤重载或重启需要的组件，确认服务可用；不无故重启其他应用。
4. **做一次最小联测**：在测试项目里导入 1 段短素材 → 读出时长 → 切一刀 → 导出并播放。通过这些检查才确认当前剪辑链路接通；没有测试的其他功能不一并算通过。
   - 只看到「MCP 已连接」不算接通；必须有一次真实的导入和导出。

## 分工建议

- 剪辑软件负责时间线、素材管理、合成与导出。
- Agent 负责读取脚本、转写、写剪辑计划、生成 MG 代码、调用生成模型、上传审阅、归档。
- 需要生成素材时使用已授权的服务；能用真实素材或解释类 MG 完成的，不为测试额外付费生成。按工具许可证和实际计算资源记录成本。

## 检查清单

- [ ] Agent 能读到脚本与素材目录
- [ ] 模型的视觉理解与审美满足要求（抽 3 帧让它描述并核对）
- [ ] 剪辑软件 MCP 已连通，且完成一次真实导入—剪切—导出
- [ ] 转写能力可用（或另有可用的语音识别服务）
- [ ] 只有本次需要生成素材时，再确认服务可用及相应预算授权

许可证参考：[Remotion 官方许可](https://github.com/remotion-dev/remotion/blob/main/LICENSE.md)、[HyperFrames 官方仓库](https://github.com/heygen-com/hyperframes)。按当前条款核对，第三方版本和价格不写成长期保证。
